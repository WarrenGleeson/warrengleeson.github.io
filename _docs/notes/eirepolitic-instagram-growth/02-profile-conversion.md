# Profile Conversion

## Status

**Planning state:** detailed investigation/experiment guide prepared.  
**Production changes:** none.  
**Priority:** highest, alongside Insights/Measurement and Discovery Hooks.  
**Dependency:** measurement is desirable before testing, but a one-time profile audit can begin immediately.

## Objective

Increase the percentage of people who discover an EirePolitic post, visit the profile, understand the account quickly, and choose to follow because the future value of following is clear.

This is a conversion problem, not primarily a content-production problem.

The intended funnel is:

```text
non-follower sees EirePolitic content
        ↓
viewer is interested enough to visit profile
        ↓
profile immediately communicates:
  - what EirePolitic is;
  - what information it provides;
  - that it is factual/non-partisan;
  - why following is useful;
        ↓
viewer follows and/or explores another post
```

The profile should therefore function as a compact landing page for people who have little prior knowledge of EirePolitic.

---

## Current state established in this planning review

### Public profile could not be reliably inspected from the open web

The current EirePolitic Instagram profile was not reliably retrievable through public web search during this review, and direct Instagram fetching was throttled.

This is **not evidence of an account or discoverability problem**. Instagram frequently restricts unauthenticated profile retrieval.

The initial implementation task must therefore perform a logged-in profile audit rather than relying on third-party search caches.

### The documentation website is not currently a general-audience landing page

The current `warrengleeson.github.io` homepage describes itself as the **Eire Politic Knowledge Base** and is oriented toward:

- technical documentation;
- repositories and systems;
- implementation details;
- operating procedures;
- architecture decisions;
- High Director-assisted development.

It also exposes public outputs, but the site as currently presented is not a purpose-built first-visit landing page for a general Instagram audience.

Therefore:

**Do not automatically make the technical documentation homepage the primary Instagram profile link merely because it exists.**

The destination linked from Instagram should be evaluated as part of this workstream.

---

## Current Instagram platform facts relevant to this workstream

These facts were reviewed in October 2026 and must be rechecked before future implementation because Instagram changes profile features over time.

- Professional accounts can inspect recommendation eligibility through Account Status; profile elements such as the bio/profile photo can affect recommendation eligibility.
- Standard Instagram accounts can pin up to three posts/reels to the profile grid.
- Instagram Plus currently expands this to six pins, but paid profile customisation is **not required for this plan** and should not be adopted merely for extra pins.
- Instagram supports multiple native profile links (currently up to five in the app), so EirePolitic does not need a third-party link-in-bio service solely to expose more than one destination.
- Professional accounts can display or hide category/contact information.

The no-cost baseline should assume three profile pins and native Instagram profile links.

---

## Core conversion hypothesis

A first-time profile visitor should be able to answer these questions in roughly five seconds:

1. **What is this account?**
2. **What will I get if I follow it?**
3. **Can I trust its political neutrality and sourcing approach?**
4. **Where should I start?**

If those answers are not immediately obvious, some discovery generated by Reels, carousels, shares, search, or collaborations will be wasted.

The profile should not attempt to explain the entire EirePolitic project. Its job is to convert attention into continued attention.

# Phase 0 — capture the current profile exactly

Before recommending any copy/design change, create a baseline record.

## Required logged-in audit

Capture the following without exposing account credentials:

### Identity

- Instagram handle/username;
- display name/name field;
- profile image;
- account type: Business or Creator;
- professional category;
- whether the category is visibly displayed;
- whether contact buttons are displayed.

### Bio

Record the bio exactly as currently displayed, including:

- line breaks;
- emojis;
- keywords;
- positioning language;
- neutrality language;
- CTA language;
- character usage.

### Links

Record:

- each active profile link;
- its visible title;
- ordering;
- destination page;
- whether the destination is mobile-friendly;
- whether it serves a general audience or a technical/developer audience;
- whether analytics/UTM parameters are available.

Do not publish private tracking parameters or credentials in documentation.

### Pinned content

For each pinned item record:

- post/Reel ID or permalink;
- content family;
- headline/cover;
- publication date;
- whether it explains the account;
- whether it demonstrates the account's strongest work;
- whether it is still current;
- performance metrics if available.

### Top grid

Review the first 9-12 visible posts from the viewpoint of a new visitor.

Record:

- how many distinct visual systems are present;
- whether the account visually reads as one coherent project;
- whether covers are understandable without reading captions;
- whether there is excessive repeated procedural terminology;
- whether the top grid demonstrates topical breadth;
- whether the account appears active and current.

### Highlights

Record:

- current Highlight names;
- cover style;
- whether content is current;
- maintenance burden;
- whether Highlights actually help a new visitor understand the account.

Do not create new Highlights solely because Instagram supports them.

### Recommendation eligibility

Open Instagram Account Status and record only the status/result, not private account information.

Confirm:

- account eligible for recommendations: yes/no;
- content currently flagged: yes/no;
- profile/bio/photo issue flagged: yes/no;
- feature restrictions: yes/no.

If anything is flagged, resolving recommendation eligibility takes priority over copy optimisation.

# Phase 1 — establish profile-conversion baseline

## Required metrics

From the Insights workstream, obtain where available:

- non-follower reach;
- profile visits/profile activity;
- follows;
- follower count by day;
- content/media that generated profile visits;
- content/media that generated follows where Meta exposes attribution.

## Primary profile-conversion KPI

Where account-level data permits:

```text
new follows / profile visits
```

This measures how effectively profile traffic becomes followers.

If Meta exposes attributed media-level follows and profile visits, also calculate:

```text
media-attributed follows / media-attributed profile visits
```

Do not manufacture this attribution when the API does not expose it.

## Supporting KPI

```text
profile visits / 1,000 non-follower accounts reached
```

This separates two stages:

- **content curiosity:** does the post cause a non-follower to investigate the account?
- **profile conversion:** does that visitor then follow?

This distinction is important.

A post can be excellent at generating profile visits while the profile itself converts poorly. Conversely, a strong profile cannot help if the content produces no profile visits.

# Phase 2 — define the profile value proposition

The profile should describe **the benefit to the follower**, not primarily the internal mechanics of the project.

## Recommended positioning components

The profile should communicate four things economically.

### 1. Subject

Plain-language description of what EirePolitic covers.

Examples of concepts to communicate:

- Irish politics;
- the Oireachtas;
- legislation;
- representatives;
- political data;
- public-policy activity.

Do not attempt to list every project/data product.

### 2. Approach

Signal why the account is distinctive and trustworthy.

Candidate concepts:

- factual;
- neutral;
- sourced;
- accessible;
- data-led;
- non-partisan.

Avoid self-congratulatory claims such as “the most unbiased” or “the truth about Irish politics.”

### 3. Follow value

Tell a visitor what recurring benefit they will receive.

Candidate concepts:

- understand what is happening in Irish politics;
- follow bills through the Oireachtas;
- see political data explained clearly;
- get recurring explainers and trackers.

### 4. Next action

The desired action should usually be follow/explore, not leave Instagram immediately.

The external link is secondary unless the linked destination provides clear additional value.

---

## Bio design rules

The final copy should be developed after the current bio is captured.

Use these constraints:

- plain English;
- immediately understandable to someone unfamiliar with parliamentary terminology;
- no partisan positioning;
- no political slogans;
- no claims of perfect objectivity;
- no long list of content series;
- no excessive emojis;
- avoid internal project terminology such as “pipeline,” “data products,” or “factory”;
- include “Irish politics” or similarly obvious subject language naturally;
- make the recurring follower benefit clear.

### Candidate structure

Not final copy:

```text
Irish politics, legislation & the Oireachtas — explained clearly.
Factual • sourced • non-partisan
Track bills, representatives, parties & political data ↓
```

This is an archetype to test, not an approved final bio.

The logged-in audit should first establish what wording is already present and whether the account has a stronger existing formulation.

# Phase 3 — display name and discoverability

The username should not be changed casually. A username change affects recognition, external links, documentation, and potentially integrations.

**Do not change the handle as part of profile optimisation unless a separate decision establishes a compelling reason.**

The display-name/name field is lower-risk and can be evaluated for clarity and search relevance.

## Candidate display-name archetypes

Examples to test conceptually:

```text
EirePolitic | Irish Politics
```

or

```text
EirePolitic — Irish Politics Explained
```

Do not adopt a phrase merely because it contains keywords. It must still read naturally as the identity of the project.

## Test questions

- Does “EirePolitic” alone explain the subject to a first-time visitor?
- Does adding “Irish Politics” materially improve clarity?
- Does “Explained” accurately describe the account without implying editorial interpretation?
- Is the field visually too long/truncated on mobile?

The display-name test should be considered a conversion/discovery experiment, but profile copy should not be changed so frequently that returning users see inconsistent branding.

# Phase 4 — profile image

The profile image has a different job from a full post graphic.

It must remain recognisable at very small sizes in:

- Feed;
- Reels;
- comments;
- shares;
- search;
- profile suggestions.

## Audit criteria

Evaluate:

- recognisability at approximately avatar size;
- sufficient contrast;
- whether any text remains legible;
- consistency with EirePolitic visual identity;
- whether it looks like an institutional information project rather than a political party;
- whether it remains recognisable on light and dark UI backgrounds.

If the current avatar already performs these functions, do not redesign it merely to create activity.

Profile-image experiments are lower priority than bio/pins because identity inconsistency carries a recognition cost.

# Phase 5 — pinned-post strategy

Pinned posts are the most important profile surface after the identity/bio because they allow EirePolitic to control the first content a visitor sees.

Use the standard no-cost allocation of **up to three pins**.

Do not pay for Instagram Plus simply to obtain six pins unless later evidence shows a specific conversion need that three cannot satisfy.

## Recommended three-pin jobs

The three pins should have **different roles** rather than merely being the three best-performing posts.

### Pin 1 — “Start here / What is EirePolitic?”

Purpose:

- explain the account;
- state neutrality/sourcing principles;
- show the major content categories;
- tell the viewer why following is useful.

Potential carousel:

1. What is EirePolitic?
2. Irish politics explained from public records and structured data.
3. Follow legislation through the Oireachtas.
4. Understand parties, representatives, polling, and political activity.
5. Sources/caveats are shown clearly.
6. Follow for recurring neutral explainers and trackers.

This should be evergreen and refreshed only when the project's scope materially changes.

### Pin 2 — strongest current demonstration

Purpose:

Show the account at its best, rather than explain it abstractly.

Candidate selection should use analytics once available.

Prefer a post that has:

- strong non-follower reach;
- high follow conversion;
- clear general-audience packaging;
- durable relevance;
- representative EirePolitic quality.

Do not pin a temporarily viral post if it misrepresents what the account normally publishes.

### Pin 3 — useful evergreen explainer / navigation post

Candidate subjects:

- how a bill becomes law;
- what Oireachtas stages mean;
- how to read an EirePolitic Bill Tracker;
- where EirePolitic gets its data;
- a guide to recurring EirePolitic series.

The objective is to give a curious visitor an immediate second useful interaction.

## Pin rotation rule

Review pins approximately monthly, not daily.

Only rotate Pin 2 regularly. Pins 1 and 3 should remain relatively stable unless evidence suggests they are weak.

This keeps recurring manual workload very low.

# Phase 6 — top-grid coherence

A profile visitor often sees more than the pinned row before deciding whether to follow.

The goal is **recognisable consistency without visual monotony**.

## Audit questions

- Can a visitor distinguish Bills, polling, party profiles, explainers, and other series?
- Do all covers look so similar that the grid appears repetitive?
- Conversely, are formats so visually different that EirePolitic looks like several unrelated accounts?
- Are formal bill titles dominating too many thumbnails?
- Does the grid show both current relevance and evergreen utility?
- Are the most recent posts intelligible without opening them?

## Desired outcome

A visitor should infer:

> “This account repeatedly explains different parts of Irish politics in a consistent, factual format.”

rather than:

> “This is a feed of parliamentary documents.”

or:

> “I cannot tell what this account is about.”

Most fixes to grid coherence should be implemented through the Discovery Hooks/Carousel workstream rather than manually curating the grid.

# Phase 7 — profile links

## Principle

Do not create exit friction merely because Instagram permits several links.

The link area should answer:

> “What useful thing can someone do outside Instagram that they cannot do easily inside the profile?”

## Candidate destinations

Possible high-value destinations include:

- a public EirePolitic “Start here” page;
- searchable bill/representative data;
- source/methodology page;
- an index of EirePolitic public outputs;
- a newsletter, if one later exists and proves useful.

## Current documentation-site constraint

`warrengleeson.github.io` is currently a technical knowledge base.

If it is to receive general Instagram traffic, create or identify a **public-audience landing page** rather than sending ordinary Instagram users directly into developer/operations documentation.

Any such public page should be clearly separated from internal/technical navigation and should not expose operational details unnecessarily.

## Native links before third-party tools

Instagram currently supports multiple native profile links.

Therefore:

- do not introduce Linktree or another paid/free intermediary merely to host multiple links;
- prefer first-party pages where available;
- use a third-party link service only if it solves a demonstrated need such as analytics or content routing better than the native links.

## Ordering

The most valuable general-audience destination should be first.

Secondary links may include:

- methodology/sources;
- public website;
- another social account only when strategically useful.

Avoid a long menu of low-value destinations.

## Tracking

If a first-party website becomes the primary destination, add privacy-appropriate source tracking such as UTM parameters where supported by the site's analytics.

The purpose is to distinguish Instagram profile referrals from general traffic.

# Phase 8 — Highlights

Highlights are **optional**, not mandatory.

They should only be used where they reduce confusion or provide durable utility without creating recurring manual work.

## Candidate Highlights

Potentially useful:

- `Start Here`;
- `Bills`;
- `Oireachtas`;
- `Data`;
- `Sources`.

Avoid creating many empty or stale categories.

## Low-maintenance rule

A Highlight should either:

- remain useful for several months;
- be populated automatically/semiautomatically from existing Story output;
- or require only occasional updates.

Do not create a strategy that requires the operator to manually maintain Stories every day simply to keep Highlights alive.

Pinned feed content is higher priority.

# Phase 9 — professional category/contact presentation

Review, but do not assume that more profile fields improve conversion.

## Category

The displayed professional category should:

- accurately describe the project;
- not imply that EirePolitic is a political party, campaign, government body, or news organisation unless that classification is actually appropriate;
- not create unnecessary ambiguity.

If no available category accurately improves understanding, keeping the category label hidden may be preferable.

## Contact button

Only expose a public contact method if there is a genuine use case such as:

- media enquiries;
- collaboration enquiries;
- factual corrections/source questions.

Do not expose a personal phone number or private email address merely because professional profiles support contact buttons.

# Phase 10 — recommendation eligibility as a profile health check

Before running profile-conversion experiments, verify that the account is eligible for recommendation to non-followers.

This matters because Account Status can identify issues involving:

- posted content;
- profile photo;
- bio;
- other recommendation restrictions.

If Account Status reports a restriction:

1. record the exact Instagram-provided reason;
2. identify the specific content/profile element;
3. determine whether the decision is correct or contestable;
4. use Instagram's supported review/edit/remove options;
5. do not perform broad deletion or mass profile changes based on speculation.

Recommendation eligibility does not guarantee reach; it only establishes that the account is eligible to participate in recommendation surfaces.

# Experiment programme

Do not change every profile element simultaneously. Doing so makes the result impossible to interpret.

## Experiment PC-01 — bio/value proposition

### Hypothesis

A bio that immediately states subject + neutral approach + follower benefit will improve follow conversion from profile visits.

### Control

Current bio.

### Treatment

One revised bio following the rules above.

### Duration

Target at least 2-4 comparable weeks, or enough profile visits to avoid reacting to a handful of visitors.

### Primary metric

```text
follows / profile visits
```

### Secondary metrics

- profile-link taps;
- absolute follows;
- profile visits.

### Confounders

Record major topical events or unusually high-reach posts during either period.

---

## Experiment PC-02 — pinned “Start Here” post

### Hypothesis

A concise pinned explainer increases conversion by reducing uncertainty about what EirePolitic offers.

### Control

Existing pinned-post arrangement.

### Treatment

Add/replace Pin 1 with the dedicated EirePolitic explainer.

### Primary metric

Follow conversion from profile visits.

### Secondary metrics

- views/reach of the pinned explainer;
- saves/shares;
- profile-link activity.

---

## Experiment PC-03 — demonstration pin

### Hypothesis

Pinning a proven high-acquisition post performs better than pinning based on recency or subjective preference.

### Method

Use the Insights dataset to identify a strong representative post by:

- non-follower reach;
- follows per 1,000 reached;
- shares/saves;
- evergreen relevance.

Rotate only Pin 2.

### Success criterion

Improved account-level profile-visit-to-follow conversion without reducing clarity/coherence.

---

## Experiment PC-04 — display name

### Hypothesis

Adding an immediately understandable subject descriptor such as “Irish Politics” improves clarity and possibly profile/search discovery.

### Control

Current display name.

### Treatment

One carefully selected descriptive variant.

### Metrics

- profile visits;
- follows;
- search-originated discovery where Instagram exposes it;
- no evidence of reduced brand recognition.

### Constraint

Do not change the username/handle for this experiment.

---

## Experiment PC-05 — profile link destination

### Hypothesis

A general-audience “Start here”/public-data destination will produce more useful engagement than a technical documentation homepage or generic multi-link page.

### Control

Current first link.

### Treatment

Purpose-built public destination if one is justified and available.

### Metrics

- profile-link taps;
- destination-page engagement;
- return/follow behaviour where measurable;
- maintenance burden.

This test may depend on a future public-site workstream.

# Risks and safeguards

## Neutrality

Do not use profile wording that makes EirePolitic sound like:

- an advocacy group;
- a campaign;
- a party;
- an anti-government/accountability campaign;
- a “both sides” opinion brand;
- a news organisation if the project is not operating as one.

Use descriptive language about what EirePolitic publishes.

## Overclaiming objectivity

Prefer “factual,” “sourced,” “non-partisan,” or “neutral political information” where accurate.

Avoid absolute claims such as:

- “completely unbiased”;
- “the truth politicians won't tell you”;
- “no spin ever.”

Those claims reduce credibility and are inconsistent with the project's careful treatment of source limitations.

## Excessive profile changes

Do not constantly edit identity fields. Frequent changes make experiment interpretation difficult and weaken recognition.

## Technical-site leakage

Do not direct a general audience into operational documentation, secrets-related material, architecture references, or developer navigation simply because the docs site is public.

## Vanity metrics

Do not evaluate the profile using follower count alone. The key question is whether profile visitors convert more efficiently after controlled changes.

Most of this workstream can proceed without user decisions.

The only information likely to require the user during the live audit is information visible only inside the authenticated Instagram account, especially:

- a screenshot or transcription of the current profile if the future chat cannot access it;
- current Account Status/recommendation eligibility;
- current Highlight/pin state if not exposed publicly;
- whether any public contact address is intentionally available for profile use.

A future LLM should ask for these only after attempting available connected/public inspection first.

# Completion criteria

This workstream is mature when:

- the account is eligible for recommendations;
- a first-time visitor can understand EirePolitic quickly;
- the bio clearly communicates subject, approach, and recurring value;
- the three pinned positions have deliberate functions;
- the first external link has a clear general-audience purpose;
- profile conversion is measured over time;
- profile changes are tested rather than made by intuition;
- recurring manual maintenance is minimal.

The intended end state is a profile that quietly performs its conversion job while the automated content/distribution system drives increasing numbers of new visitors into it.
