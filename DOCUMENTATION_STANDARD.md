# Documentation Standard

This repository is the public presentation layer for project documentation.

The canonical repository documentation standard now lives in `General_Director` under:

- `director-pack/REPOSITORY_STANDARD.md`
- `director-pack/DOCUMENTATION_STANDARD.md`

Use those files for repository documentation rules, lifecycle terms, verification guidance, archive rules, AI-agent guidance, and `project.yaml` requirements.

## Site-specific rules

This repository may keep presentation-specific copies, summaries, navigation pages, and generated content needed for GitHub Pages.

Those copies are not canonical when the source project has its own repository documentation.

When site content conflicts with source-repository documentation:

1. treat the source repository as authoritative for durable project knowledge;
2. verify live systems separately for current operational state; and
3. update this site to match rather than creating a second competing standard.

## Publication

- Public-repository documentation may be published when `project.yaml` permits it.
- Private-repository material must not be published unless explicitly approved and sanitized.
- Portfolio publication is separate from technical documentation publication.
- Preserve stable public URLs where practical.

## Historical material

Do not delete migration-era or superseded documentation in bulk. Archive or replace it incrementally when the canonical source is clear and the public URL can be preserved safely.
